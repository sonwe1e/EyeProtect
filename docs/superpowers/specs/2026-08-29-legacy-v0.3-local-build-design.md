# EyeProtect Legacy v0.3 Local Build Design

## Goal

Build a Windows x64 portable executable from commit
`ee79dc9f0c6035106804fabc0650adef6b6f5e64`. The executable must preserve the
historical v0.3 interface and reminder behavior, including the optional forced
rest mode that unlocks after 30 artwork clicks or after the original countdown
(30 seconds for eye reminders and 60 seconds for walk/combined reminders).

The build must not read, rewrite, lock, or delete data and startup state owned
by the current EyeProtect application.

## Historical baseline

`ee79dc9` is the final clean source commit that retains the 30-click behavior.
Its source tree is identical to `8fa2de3` and `cf1a8e4`; the intervening commits
only added and then removed a generated EXE. The next source commit, `34f96a5`,
is a large v0.4 product change that removes `forceRest` and click unlocking.
There is no later small-fix commit that preserves the requested behavior.

The build will use the dependency versions in the historical `package-lock.json`.
Dependencies will not be upgraded, and later product or runtime commits will not
be cherry-picked.

## Minimal isolation repair

The historical portable build uses the temporary unpacked process path for its
data and startup shortcut. That loses settings and can point auto-start at a
temporary executable. The legacy build will receive only the following
operational repair:

- Resolve the original portable folder from `PORTABLE_EXECUTABLE_DIR`, falling
  back to the packaged executable directory.
- Store settings beside the delivered EXE in `data-legacy-v0.3/`.
- Keep `EYEPROTECT_DATA_DIR` as an explicit override for automated tests.
- Set Electron `userData` to
  `data-legacy-v0.3/electron-profile/` before requesting the single-instance
  lock, so current and legacy builds can run independently.
- Resolve auto-start from `PORTABLE_EXECUTABLE_FILE`, with the runtime executable
  as a fallback.
- Use the distinct shortcut name `EyeProtect Legacy 0.3.lnk`.
- Give the package a distinct application identity and artifact name:
  `EyeProtect-Legacy-0.3.0-win-x64.exe`.

These changes affect only storage, process identity, packaging metadata, and
startup targeting. They must not change the UI, reminder schedule, countdowns,
force-rest default, click threshold, or reminder actions.

## Build isolation and output

Implementation and packaging will happen in a Git worktree based on `ee79dc9`,
not in the current dirty worktree. The historical lock file will be installed
with `npm ci`. The requested deliverables will be copied to the ignored local
folder `artifacts/legacy-v0.3/`:

- `EyeProtect-Legacy-0.3.0-win-x64.exe`
- `EyeProtect-Legacy-0.3.0-win-x64.exe.sha256.txt`
- `BUILD-INFO.md` containing the base commit, local repair commit, build commands,
  version information, signature status, and verification results.

Generated dependencies, build outputs, runtime data, and EXE files will not be
committed.

## Verification

Automated verification must include:

1. Tests for portable folder resolution, explicit test-directory override,
   legacy profile isolation, original executable targeting, and legacy shortcut
   naming.
2. Historical `npm run typecheck` and `npm test`.
3. `npm run package` using the historical dependency lock.
4. File existence, Windows version metadata, expected unsigned status, size,
   and SHA-256 recording.
5. A packaged runtime check showing that settings are written only to the
   sibling `data-legacy-v0.3/` directory and survive restart.
6. A reminder interaction check performed before the countdown expires: 29
   artwork clicks remain locked, the 30th click unlocks all three actions, and
   completing the reminder returns to the pet surface.
7. A countdown-path check showing that an eye reminder unlocks after roughly
   30 seconds without clicks.

If GUI automation cannot reliably distinguish the exact artwork click count,
the automated checks will be supplemented by a visible manual verification and
the limitation will be recorded in `BUILD-INFO.md`; it will not be silently
reported as automated coverage.

## Non-goals

- Recreating an unverified 20-click variant.
- Incorporating v0.4, v0.5, or current EyeProtect features.
- Upgrading Electron or other dependencies.
- Signing, publishing, installing, or replacing the current EyeProtect build.
- Reading or migrating current EyeProtect user data.
